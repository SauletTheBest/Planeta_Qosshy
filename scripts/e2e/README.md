# Сквозные проверки (end-to-end)

Эти скрипты запускают **настоящий** магазин, **настоящий** тестовый банк, временную
PostgreSQL и почтовый сервер-ловушку [Mailpit](https://mailpit.axllent.org/), а потом
ходят по сайту через `curl`: как покупатель, как администратор и как банк.
Каждая строка `PASS`/`FAIL` — одна проверка.

| Скрипт | Что проверяет | Проверок |
|---|---|---|
| `testA.sh` | миграция 000006 на старых данных, email без учёта регистра, лимиты по IP, страницы каталога, профиль, вложения в поддержку, JSON-логи | 60 |
| `testB.sh` | админка: заказы, отправка/доставка, отмена с возвратом денег, банк недоступен, поздняя оплата, роли и блокировка, CSRF, миграция 000007 вниз/вверх | 67 |
| `testC.sh` | миграция 000008 (хеши старых ссылок), корзина «всё или ничего», сброс пароля, выход на всех устройствах, ссылка подтверждения 24 ч, загрузка фото | 57 |

Ядро тех же гарантий (гонка за последний товар, корзина, истечение резерва,
идемпотентный webhook) есть и в Go-тестах `shop/integration_test.go` — они
работают на любой ОС и запускаются в CI.

## Как запустить

Нужны: **Windows + Git Bash**, Docker Desktop, Go, Python 3, `openssl`
(есть в Git Bash). Банк должен лежать рядом: `../planeta_qosshy_microservice`.

```bash
scripts/e2e/build.sh       # собрать магазин, банк и две старые версии магазина
bash scripts/e2e/testA.sh  # потом testB.sh, testC.sh
```

Свободными должны быть порты 8080, 8081, 1025, 8025 и 55440–55443.

## Безопасность

Скрипты создают и удаляют **только свои** контейнеры с префиксом `pq-` и пишут
только в `/tmp/planeta-e2e`. Твою базу из `docker-compose.yml` они не трогают.

## Почему так странно в паре мест

- **Кириллица идёт через файлы** (`printf ... > file`, `curl -F "subject=<file"`):
  `curl.exe` в Git Bash получает аргументы командной строки не в UTF-8.
- **`cygpath -m` для `-F "file=@path;filename=..."`**: Git Bash принимает `;` за
  разделитель списка путей и портит аргумент.
- **`-b jar -c jar`**: flash-сообщения едут в новой cookie, и curl должен её сохранить,
  как браузер.
- **`X-Forwarded-For` с разными адресами**: магазин запускается с
  `TRUSTED_PROXIES=127.0.0.1`, чтобы каждая проверка была «отдельным клиентом» и не
  упиралась в лимиты по IP.
